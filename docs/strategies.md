# 六种上下文裁剪策略详解

## 概述

TCK 提供六种上下文裁剪策略，每种策略针对不同的使用场景设计。策略可在对话过程中随时切换，切换后立即生效。

---

## 1. 首尾保留（headTail）

**机制：** 保留消息列表开头 N 条 + 结尾 M 条，中间部分省略。

**适用场景：**
- 多轮长对话，开头有重要的系统设定
- 需要保持初始约束一致性
- 中间讨论已充分但无需每轮回顾

**示例：**
```
[消息1: 系统设定] ✅ 保留
[消息2: 需求描述] ✅ 保留
[消息3: 第1轮讨论] ❌ 省略
[消息4: 第2轮讨论] ❌ 省略
...
[消息N-2: 第N-2轮讨论] ✅ 保留
[消息N-1: 上一轮回复] ✅ 保留
[消息N: 当前请求]   ✅ 保留
```

**参数：** 可配置头部保留条数和尾部保留条数。

---

## 2. 手动截断（manualCut）

**机制：** 用户指定一条消息作为截断点，该消息之后的内容不送入模型。

**适用场景：**
- 一个讨论阶段结束，进入新阶段
- 前面走过弯路，不想让模型再看到
- 归档已完成的子任务

**使用方式：** 在消息列表中选择截断点，截断点之前的内容投喂给模型，之后的内容仅保存在记忆层。

---

## 3. 滑动窗口（slidingWindow）

**机制：** 只保留最近 N 条消息，更早的消息不送入模型。

**适用场景：**
- 快速迭代、短期任务
- 前面讨论已过时
- 需要最高响应速度

**参数：** 可配置窗口大小（保留的消息条数）。

---

## 4. 过期时间（expireTime）

**机制：** 设定一个时间窗口，只保留该时间范围内的消息。

**适用场景：**
- 按天/周管理的任务
- 跨日期的工作，每天只关注当天
- 需要按时间维度隔离上下文

**参数：** 可配置过期时长（如 24 小时、7 天等）。

---

## 5. 字段截取（fieldCut）

**机制：** 只保留消息中的特定字段（如只保留用户问题和模型最终结论，省略中间推理过程）。

**适用场景：**
- 信息密度高但冗余多的对话
- 需要保留结论但过滤过程
- 对话中包含大量中间推理步骤

**参数：** 可配置保留哪些字段。

---

## 6. 全量上下文（full）

**机制：** 不裁剪，所有消息全部送入模型。

**适用场景：**
- 对话初期，消息较少
- 重大决策点，需要模型看到完整历史
- 对话内容都是关键信息

**注意：** 此策略 Token 消耗最高，建议仅在必要时使用。

---

## 策略组合建议

实际使用中，可以在不同阶段切换不同策略：

```
阶段1（需求明确）  → full         全量，确保信息完整
阶段2（方案讨论）  → headTail     首尾保留，保持设定一致
阶段3（快速迭代）  → slidingWindow 滑动窗口，快速推进
阶段4（阶段切换）  → manualCut    截断，归档已完成
阶段5（重大决策）  → full         全量，确保决策质量
```
